# DELeGANce Screening Pipeline

DELeGANce is an end-to-end pipeline for DNA-encoded library (DEL) sequencing analysis. It covers FASTQ preprocessing, barcode decoding, hit calling (GLM-based), and reporting (static and interactive).

---

## Quick Start (Beginner)

Where to run commands
- If you are in the repo root (this folder), run `python3 run_delegance_pipeline.py`.
- If you call from a parent folder, prefix paths with the repo directory name.
- `--output-dir` is resolved relative to your current working directory.

### 1) Create a clean environment
Option A (recommended, reproducible):
```bash
conda env create -f environment.yml
conda activate delegance
```

Option B (manual install):
```bash
conda create -n delegance python=3.10
conda activate delegance
conda install -c conda-forge -c bioconda fastp
conda install -c conda-forge numpy pandas scipy matplotlib bokeh narwhals openpyxl
# Optional (recommended for structure + speed)
conda install -c conda-forge rdkit
```

GPU (optional):
```bash
conda install -c pytorch -c nvidia pytorch-cuda=12.1
```

### 2) Run the pipeline
```bash
python3 run_delegance_pipeline.py \
  --fastq-dir 00_input_fastq \
  --bbinfo 00_BB_information.txt \
  --output-dir DELeGANce_out/my_run \
  --threads 6 \
  --mismatch hp_op_cp \
  --r1 R1C1 R1C2 R1C3 R1C4 \
  --r2 R2C1 R2C2 R2C3 R2C4 \
  --neg NEG_R1 NEG_R2 \
  --del2 DEL2
```

### 3) Open the results
- `DELeGANce_out/my_run/index.html`
- `DELeGANce_out/my_run/03_normalized/<preset>/interactive_hits.html`

## Inputs (What You Need)

### 1) FASTQ naming
Each sample should have paired reads:
```
<SAMPLE>_1.fastq.gz            # tested first (also <SAMPLE>.1 / <SAMPLE>-1, .fq, uncompressed)
<SAMPLE>_R1_001.fastq.gz       # bcl2fastq style: <SAMPLE>_R1[_<lane/chunk>].fastq.gz; the base is split at the LAST _R1/_R2 token
```
`<SAMPLE>` becomes your column name in downstream tables. Note that for bcl2fastq names the whole base is kept, so
`R1C1_S1_L001_R1_001.fastq.gz` yields the sample `R1C1_S1_L001` (pass that name to `--r1`, rename the files, or use
`--fastq-regex` with `(?<base>...)` / `(?<read>[12])` groups to drop the `_S1_L001` tokens). Sample names may themselves contain `_R1`/`_R2`
(e.g. `NEG_R1_1.fastq.gz`). A read number assigned twice to one sample, an unpaired file, an empty (0-byte) file or a
directory with no pair aborts preprocessing with an explicit message. Non-standard names: pass
`--fastq-regex` to `01_preprocess_reads.pl` with named groups `(?<base>...)` and `(?<read>[12])`.

### 2) BB information file (tab-delimited)
Minimum 7 columns in this exact order (header optional):
```
type    seq     bb_id   cycle   tag_id  lib_id  smiles
```
Notes:
- `type` must include CODON/HP/OP/CP
- `cycle` is 1/2/3/4 for codons
- `lib_id` is required if multiple libraries exist
- BB files are user-provided and are not stored in this repository

### 3) Sample columns for hit calling
These must match the column names inside:
```
DELeGANce_out/<run_name>/02_decoded/raw_counts_matrix.tsv
```
Use those exact names in `--r1`, `--r2`, `--neg`, `--del2`.

## What the Pipeline Does (High Level)

1) Preprocess (fastp)
   - trims, merges pairs, creates `01_fastp_out/`
2) Decode (HP/OP/Codons/CP)
   - builds `02_decoded/` with raw/scaled count matrices
3) Hit calling + reports
   - GLM scoring plus static and interactive reports in `03_normalized/`

---

## Decoding Logic (Important)

The decoder expects the read layout:
```
HP - OP - Codon1 - Codon2 - Codon3 - (Codon4) - CP
```

Rules enforced by the code:
- Decode: HP/OP/CP allow 1-bp mismatch (substitution, insertion, deletion) when `--mismatch hp_op_cp` is enabled.
- Preprocess: mismatch indexing is substitution-only for HP/OP/CP (codons are always perfect match only). This does not remove indel tolerance during decode.
- Use `--mismatch hp_op_cp|none` to control mismatch handling across preprocess + decode.
- Codons are perfect match only
- Order is strict; violations are marked undecoded
- Small overlap or insertion between blocks is allowed within `ADJ_TOL`
- revcomp is handled by re-orienting the read and applying the same rules

Key parameters (advanced):
- `--adj-tol` in `02_decode_reads.pl` (default 3)
- `--length-tol` in `02_decode_reads.pl` (default 5; `--auto-tol-from-fastp 1` derives it from the fastp insert-size peak width)
- Length window policy in `02_decode_reads.pl`: by default (`--auto-insert-detect 1`) the accepted read lengths are the Top-K fastp
  insert-size peaks (>= `--peak-min-frac` of reads) +/- `--length-tol` ("multi" mode; `length_passed_reads` counts reads within any
  of these centres). `--auto-select-window 1` (`-W 1`) instead selects a single 3-cycle / 4-cycle window (or `both`) from the fastp
  support, and `--auto-center-window 1` (`-C 1`, requires `-W 1`) re-centres that window on the nearest fastp peak. Both default to 0.
- Anchor design requirement: HP/OP/CP sequences of the same library must differ by more than 2 edits; a 1-bp variant that collides
  with another anchor is dropped with a warning (`WARN ... variant skipped`) and only perfect matches remain for that variant.
- `--max-cp-cands` / `--max-anchor-cands` in `02_decode_reads.pl` (0 = no limit; default 0)

## Resume and Partial Runs

If a run is interrupted, the pipeline checks completion markers before skipping stages:
- Preprocess: requires merged FASTQs, `BB_information_fixed.tsv`, and the marker file `01_fastp_out/.preprocess_done`
  (written only when every fastp job succeeded; removed at the start of each preprocess run)
- Decode: requires `raw_counts_matrix.tsv` and the marker file `02_decoded/.decode_done`
- Legacy runs without marker files are accepted when the stage log contains `All done.` (the logs are append-mode, so this
  fallback cannot distinguish an old success from a failed rerun — rerun with `--force-*` if in doubt)

If these markers are missing, the pipeline reruns the stage.

## How to Pick Hits (Beginner)

The QC export adds two helper fields:
- `Tier`: A = consensus hit with no QC flags (recommended), B = consensus hit with QC flags other than `NEG_hard_fail` (control or risk check); consensus hits with `NEG_hard_fail=TRUE` are labelled `Other`
- `PickGroup`: TierA_Top, TierA_Diverse, TierB_Control

Recommended starting set: TierA_Top plus a few TierB_Control for controls.

## Column Reference (Key Outputs)

This section explains columns used in major TSV outputs. Sample-specific columns use the exact sample names from `raw_counts_matrix.tsv` and are described as patterns.

### 02_decoded/raw_counts_matrix.tsv
- `lib_id`: library ID assigned from CP (or NA if unknown)
- `id`: decoded tag ID string (cycles_BB1_BB2_BB3_[BB4])
- `<sample>`: raw decoded read count for that sample

### 02_decoded/scaled_counts_matrix.tsv
- Same columns as `raw_counts_matrix.tsv`
- Values are CPM scaled by `--scaling-denom` (default: `sample_decoded`)

### 02_decoded/sample_stats.tsv
- `sample`: sample name derived from FASTQ basename
- `total_reads`: merged reads processed
- `length_passed_reads`: reads within the active length window (default multi mode: within `--length-tol` of any fastp Top-K peak; see `length_window_stats.tsv` for the centres used)
- `decoded_reads`: reads that passed decoding
- `decode_rate_pct`: decoded_reads / total_reads * 100

### 02_decoded/decoding_summary.tsv
- `sample`: sample name
- `total_reads`: merged reads processed
- `decoded_reads`: reads that passed decoding
- `no_cp`: reads without a valid CP
- `no_op`: reads without a valid OP
- `no_hp`: reads without a valid HP
- `codon_fail`: reads failing codon matching (codons require perfect match)
- `len_out_of_range`: reads outside the accepted length window
- `order_violation`: reads with HP/OP/Codon/CP order violations

### 02_decoded/qc_checks.tsv
- `sample`: sample name
- `codon_len_not9`: decoded reads where codon length is not 9
- `order_violation`: decoded reads with order violations
- `cp_len_out_of_27_29`: decoded reads with CP length outside 27 to 29

### 03_normalized/<preset>/05_hybrid_annot.tsv
- `LIB_ID_x`: library ID from decoded tags (CP-based)
- `ID_x`: decoded tag ID from count matrix
- `cycles`: 3 or 4 cycles inferred from the tag
- `BB1_x`, `BB2_x`, `BB3_x`, `BB4_x`: decoded BB IDs (may include LIB suffix)
- `CP_x`: decoded CP ID
- `mean_R1_norm`, `mean_R2_norm`: mean normalized counts across R1/R2 columns
- `DEL2_norm`: normalized DEL2 count
- `CV_R1`, `CV_R2`: coefficient of variation across R1/R2 replicates
- `LFC_R1_vs_DEL2_baseline`, `LFC_R2_vs_DEL2_baseline`: baseline log2 fold-change vs DEL2
- `mean_NEG1_norm`, `mean_NEG2_norm`: mean normalized NEG counts (for each NEG set)
- `LFC_NEG_R1_vs_DEL2`, `LFC_NEG_R2_vs_DEL2`: NEG vs DEL2 log2 fold-change (baseline, pseudocount-stabilised)
- Note: GLM and baseline LFCs share the same pseudocount (`--pseudocount_k`, applied to both the DEL2 offset and the observed counts), so a zero-count condition yields the bounded floor `log2(epsk / (DEL2_norm + epsk))` on every backend (numpy / torch-cpu / torch-cuda)
- `delta_NEG_R1`, `delta_NEG_R2`: NEG deltas for R1/R2
- `delta_R1`, `delta_R2`: deltas for R1/R2 (effect size)
- `LFC_NEG_R1_vs_DEL2_glm`, `LFC_NEG_R2_vs_DEL2_glm`: GLM-adjusted NEG log2 fold-change
- `LFC_R1_vs_DEL2`, `LFC_R2_vs_DEL2`: GLM-adjusted log2 fold-change vs DEL2
- `mu_NEG_R1_hat`, `mu_NEG_R2_hat`, `mu_R1_hat`, `mu_R2_hat`: GLM fitted mean counts
- `alpha_for_penalty`: dispersion parameter used for penalty (capped)
- `delta_NEG`: combined NEG delta
- `LFC_NEG_vs_DEL2`: combined NEG log2 fold-change
- `mu_NEG_hat`: GLM fitted mean for NEG
- `DEL2_sum`: sum of DEL2 counts used by GLM
- `LFC_R1_vs_DEL2_baseline_glm`, `LFC_R2_vs_DEL2_baseline_glm`: GLM baseline LFC values
- `LFC_R1_vs_DEL2_used`, `LFC_R2_vs_DEL2_used`: LFC values used for scoring after gating
- `LFC_NEG_R1_vs_DEL2_used`, `LFC_NEG_R2_vs_DEL2_used`: NEG LFC values used for scoring
- `NEG_control_used`: NEG control selection used in scoring
- `LFC_NEG_vs_DEL2_used`: combined NEG LFC used for scoring
- `delta_NEG_used`: NEG delta used for penalty
- `NEG_penalty_used`: NEG penalty mode used in scoring
- `E_component`: effect-size term used in HitScore
- `W_count`: count-based weight term (logistic of mean counts)
- `E_for_synthon`: effect term used for synthon scoring
- `SynthonScore`: synthon consistency score
- `SynthonBonus`: multiplicative bonus (1 + rho_syn * SynthonScore)
- `Penalty_NEG_R1`, `Penalty_NEG_R2`: NEG penalties per arm
- `Penalty_NEG`: total NEG penalty
- `Penalty`: total penalty (CV/alpha and NEG penalties)
- `HitScore_GLM`: GLM hit score (E_component * W_count * SynthonBonus - Penalty)
- `HitScore_pct`: percentile of HitScore_GLM within the run (0 to 100)
- `GLM_hit`: GLM pass/fail flag
- `avg_R1`, `sd_R1`, `avg_R2`: ReadScaler mean and sd of size-factor normalised counts (count / sf_lib,sample; the same size factors as the GLM offsets)
- `zscore_avgR1`: z-score of avg_R1
- `mean_log2FC_DEL2`, `sd_log2FC_DEL2`, `se_log2FC_DEL2`, `p_DEL2`: DEL2 ReadScaler stats
- `mean_log2FC_BEAD`, `sd_log2FC_BEAD`, `se_log2FC_BEAD`, `p_BEAD`: BEAD ReadScaler stats (R1)
- `mean_log2FC_BEAD_R2`, `sd_log2FC_BEAD_R2`, `se_log2FC_BEAD_R2`, `p_BEAD_R2`: BEAD ReadScaler stats (R2)
- `log2Boost_R2vsR1`: log2 boost of R2 vs R1
- `mean_log2Boost_R2vsR1_paired`, `sd_log2Boost_R2vsR1_paired`, `se_log2Boost_R2vsR1_paired`, `n_pairs_paired`, `p_BoostPaired`: paired boost stats
- `q_DEL2`, `q_BEAD`, `q_BEAD_R2`, `q_BoostPaired`: BH-adjusted q-values (one-sample t-test across replicates; with fewer than 4 replicates
  these have very little power, so the q-value gates (`--max_q_bead`, `--max_q_bead_r2`, `--max_q_paired_boost`, as set e.g. by the
  `neg_heavy` / `very_hard` presets) are disabled with a `[WARN]` when the corresponding condition has fewer than 4 replicates; the
  effect-size gates and `--neg_gate_mode` are kept. List a parameter name in `--auto_lock` to keep its q gate anyway)
- `--auto_tune 0` disables both the pre-GLM (`w_neg/w_r1/w_r2/fix_neg_poisson`) and post-GLM (`t0/slope/c1..c3/w1..w3/lambda_*/rho_syn`)
  auto-tuning so the CLI values are used verbatim; `--auto_lock <name ...>` keeps individual parameters fixed while tuning the rest.
  The parameters actually used are written to `OUTDIR/hit_params_used.json` (or `--auto_save_json PATH`), and a minimal
  `OUTDIR/hit_params.json` (sample-column mapping) is written when 03 is run stand-alone.
- `mad_log2FC_DEL2`, `mad_log2FC_BEAD`, `mad_log2Boost_R2vsR1_paired`: MAD values for variance penalty
- `var_penalty`: variance penalty used in ReadScaler
- `HitScore_RS`: ReadScaler hit score
- `fail_reasons`: semicolon list of QC failures
- `pass_filters`: QC pass flag
- `<sample>`: raw decoded read count for that sample
- `<sample>_CPM`: CPM for that sample
- `bb1_id`, `bb1_smiles`, `bb1_tag_uid`, `bb1_tag_seq`: BB1 metadata from BB info file
- `bb2_id`, `bb2_smiles`, `bb2_tag_uid`, `bb2_tag_seq`: BB2 metadata
- `bb3_id`, `bb3_smiles`, `bb3_tag_uid`, `bb3_tag_seq`: BB3 metadata
- `bb4_id`, `bb4_smiles`, `bb4_tag_uid`, `bb4_tag_seq`: BB4 metadata
- `BB_SMILES_CONCAT`: concatenated BB SMILES (for clustering)
- `ID_y`, `LIB_ID_y`, `BB1_y`, `BB2_y`, `BB3_y`, `BB4_y`, `CP_y`: BB info merge fields
- `RS_pass`: ReadScaler pass flag
- `NEG_hard_fail`: hard fail due to NEG gating
- `LFC_NEG_centered`: NEG vs DEL2 LFC centered by null subset
- `delta_NEG_centered`: centered NEG delta
- `NEG_center_fail`: fail if LFC_NEG_centered exceeds threshold
- `LFC_NEG_centered_R1`, `NEG_center_shift_R1`: R1 centering detail
- `LFC_NEG_centered_R2`, `NEG_center_shift_R2`: R2 centering detail
- `Consensus_hit`: GLM_hit and RS_pass

### 03_normalized/<preset>/top<N>_hits.tsv
- Inherits columns from `05_hybrid_annot.tsv` (key columns ID/LIB_ID/BB1..BB4/CP are also available as `*_x` aliases when
  03 emits plain names; `*_CPM` and raw sample count columns are appended at the end)
- Adds `rank` (1 = best; ties: HitScore_RS desc, then ID asc; rows without a numeric score are excluded from ranking)
- Adds `cluster_id`, `cluster_size`, `cluster_rep`, `cluster_medoid` (cluster_id=NA and 0 flags when clustering is disabled,
  skipped or RDKit is unavailable)
- Note: `compound_key` (BB1|BB2|BB3|BB4 with LIB suffix removed, missing BB = `NA`), `rank_pct` and `score_z` are columns of the
  `06_compare_top_hits.py` / `07_tiered_report.py` outputs (see below); they are not written to this file. `export_full_runs.py`
  uses the same `compound_key`.

### 03_normalized/<preset>/top<N>_recommended.tsv
- Same columns as `top<N>_hits.tsv`
- Rows filtered by QC rules (Consensus_hit, GLM_hit, RS_pass, NEG_hard_fail, if columns exist)

### 03_normalized/<preset>/top<N>_diverse.tsv
- Same columns as `top<N>_recommended.tsv`
- One row per `cluster_id` among filter-passing rows: the cluster representative (per `--cluster-rep`) when it passes the QC
  filters, otherwise the best-ranked passing member; unclustered rows (cluster_id=NA) are kept; capped at `--recommend-n`.
  Equals `top<N>_recommended.tsv` when no clustering was performed.

### 03_normalized/<preset>/top<N>_bb_frequency.tsv
- `bb_col`: BB column name (BB1_x, BB2_x, BB3_x, BB4_x, CP_x)
- `bb`: BB ID (LIB suffix removed). Missing values (NA) are not counted as building blocks.
- `count`: number of appearances in top N
- `pct`: percent of top N
- `lib_ids`: unique LIB_ID list for the BB
- `lib_counts`: per-LIB_ID counts as `LIB:count` pairs, sorted by count desc (`lib_ids` is sorted alphabetically)

### 03_normalized/<preset>/top<N>_clusters.tsv
- `cluster_id`: cluster label
- `cluster_size`: number of hits in the cluster
- `rep_index`, `medoid_index`: 0-based position in the table as it was passed to clustering (before the final sort), not the
  row number of the saved TSV; use `rep_compound_key` / `rep_ID_x` to identify the representative (same for
  `compare_top<N>_<label>_clusters.tsv` and `tier_report_clusters.tsv`)
- `rep_ID_x`, `rep_score`, `rep_BB1_x`..`rep_BB4_x`, `rep_CP_x`, `rep_compound_key`: representative fields
- `medoid_index`, `medoid_ID_x`, `medoid_score`, `medoid_compound_key`, `medoid_avg_sim`: medoid fields

### compare_top<N>_union_top<N>.tsv and compare_top<N>_overlap_top<N>.tsv
- `compound_key`: BB1|BB2|BB3|BB4 with LIB suffix removed
- `pattern`: membership pattern (example: A, B, A+B)
- `n_runs`: number of runs containing the compound in top N
- `<label>_score`: per-run score (HitScore_GLM or HitScore_RS)
- `<label>_score_z`: z-score of the per-run score
- `<label>_HitScore_pct`: per-run HitScore percentile
- `<label>_rank`: rank within that run
- `<label>_rank_pct`: rank percentile within that run
- `<label>_score`, `<label>_score_z`, `<label>_HitScore_pct` are empty (NaN, never -inf) when the compound has no finite score
  in that run; `<label>_rank` / `<label>_rank_pct` are computed over compounds with a finite score only
- `<label>` is taken from `--labels`; when omitted, a run given as a directory is labelled by its basename and a run given as a
  `05_hybrid_annot.tsv` path as `<run>_<preset>`; duplicate derived labels get `_1`, `_2`, ... suffixes (a warning is printed;
  this also changes the `compare_top<N>_<label>_*.tsv` file names). Duplicate explicit `--labels` are an error.

### compare_top<N>_pattern_counts.tsv
- `pattern`: membership pattern
- `count`: number of compounds in the pattern
- `pct`: percentage of the union

### compare_top<N>_<label>_top<N>.tsv
- Same columns as `top<N>_hits.tsv` for that run

### compare_top<N>_<label>_recommended<M>.tsv
- Same columns as `top<N>_recommended.tsv` for that run

### compare_top<N>_<label>_diverse.tsv
- Same columns as `top<N>_diverse.tsv` for that run; contains cluster representatives only. When clustering is not performed
  (`--cluster 0`, `--include-summary 0`, RDKit missing, no `bb*_smiles` columns, or no valid fingerprints) the file is still
  written but contains only the header, and an `[INFO] clustering not performed ...` line is printed.

### tier_report_*_all_candidates.tsv and tier_report_*_specific.tsv
(written by `06_compare_top_hits.py --include-specificity 1` under `--spec-prefix`, default `tier_report`, and by
`07_tiered_report.py` under `--out-prefix`)
- Inherits columns from `top<N>_hits.tsv`
- Adds `source_run` (06 outputs): label of the run whose row was kept for this compound after de-duplication (priority
  active > inactive > both); inherited columns such as `HitScore_pct`, `GLM_hit`, `LFC_*`, `bb*_smiles` come from that run
- Adds `source_role` (06 outputs): `active`, `inactive` or `both` (role of `source_run`)
- Adds `active_present`, `inactive_present`, `both_present` (0/1; 07 outputs): 1 when the compound has a finite score in that run
  (i.e. it was ranked there); 0 when it is missing from that run's `05_hybrid_annot.tsv` or its score is NaN. Use these to
  distinguish "absent" from `rank_pct = 0`.
- Adds `rank`: rank in the combined candidate pool (by `active_score`)
- Adds `active_score`, `active_rank`, `active_rank_pct`, `active_score_z`: metrics from the active run
  (`active_score` is the active run's score even for inactive/both-only candidates)
- Adds `active_hit_pct`: HitScore_pct from the active run (falls back to active_rank_pct)
- Adds `inactive_score`, `inactive_rank_pct`: metrics from the inactive run
- Adds `both_score`, `both_rank_pct`: metrics from the optional both run (NaN if not provided)
- Missing scores (`<score_col>`, `active_score`, `inactive_score`, `both_score`, `group_rank_score`) are written as empty cells
  (NaN), never `-inf`; tied scores share the same `*_rank`/`*_rank_pct` (method=min)
- Adds `selectivity_score`: active_rank_pct - inactive_rank_pct
- Adds `inactive_selectivity_score`: inactive_rank_pct - active_rank_pct
- Adds `both_specific_score`: (active_rank_pct + inactive_rank_pct) / 2
- Adds `group_code`: Active-specific, Inactive-specific, Both-specific, or Other
- Adds `active_enrich`, `inactive_enrich` (07): per-run enrichment = `--enrich-agg` (default median) of the run's `<sample>_CPM`
  columns (raw counts if no CPM), excluding NEG samples (`--neg-samples`), the DEL2 baseline (`--del2`, default `DEL2`) and
  `--exclude-samples` (default `DEL234`)
- Adds `both_enrich` (07): `--common-enrich` (default min) of active_enrich and inactive_enrich
- Adds `specificity_score`: selectivity_score (Active-specific/Other), inactive_selectivity_score (Inactive-specific) or
  both_specific_score (Both-specific)
- Adds `group_rank_score` (07): the value `group_rank` is based on — the group's enrichment (`--rank-by enrichment`, default) or
  `specificity_score` (`--rank-by specificity`); empty when no enrichment column is available
- Adds `group_rank`: rank within group by `group_rank_score` (ties broken by specificity_score, then the run score)
- Adds `cluster_id`, `cluster_size`, `cluster_rep`, `cluster_medoid`: present whenever `--cluster 1` (all `NA`/0 if clustering
  could not be performed). `cluster_rep` = best score, `cluster_medoid` = highest mean within-cluster similarity; both are
  selected per (group, cluster), so a cluster spanning two groups has one representative in each group's `*_diverse.tsv`
- Adds `group`: display label (from `--labels`; duplicate derived labels get `_2`, `_3` ... suffixes)
- Adds `<label>_<sample>` and `<label>_<sample>_CPM`: raw and CPM columns from each run with label prefix; the unprefixed
  `<sample>` / `<sample>_CPM` columns are coalesced active → inactive → both
- 07 with `--both-run` also writes `<prefix>_all_candidates_<both_label>.xlsx`

### tier_report_*_diverse.tsv
- Same columns as tier_report_*_specific.tsv
- Cluster representatives (cluster_rep=1 or cluster_medoid=1), re-selected per (group, cluster)
- Empty (header only) when clustering did not run (`--cluster 0`, or RDKit / `bb*_smiles` unavailable); 07's final hit
  selection then falls back to the full group lists

### run_full_validation.py outputs (decode_validation_summary.tsv)
- `run`: validation run name
- `sample`: sample name
- `total_reads`, `length_passed_reads`, `decoded_reads`, `decode_rate_pct`: same definitions as decode stats
- `no_cp`, `no_op`, `no_hp`, `codon_fail`, `len_out_of_range`, `order_violation`: decode failure counts
- `qc_codon_len_not9`, `qc_order_violation`, `qc_cp_len_out_of_27_29`: QC check counts
- `validation_sampled`: number of decoded reads actually re-validated (`--decoded-max-lines` / `--decoded-sample` cap)
- `validation_pass`: decoded reads that match expected BBs/length/order in validation
- `validation_fail`: decoded reads that fail validation checks
- `validation_cycles_mismatch`: decoded reads with cycle count mismatch
- `validation_cycles_out_of_range`: decoded reads whose cycle count is not 3 or 4 (counter `cycles_out_of_range`)
- `validation_length_filter_reject`: decoded reads failing expected length
- `validation_lib_unknown`: decoded reads with unknown library ID
- `length_conf_missing`: missing length configuration for the sample
- `undecoded_sampled`: number of undecoded reads sampled for validation
- `undecoded_unexpected_decoded`: sampled undecoded reads that appear decodable
- `undecoded_len_reject`: sampled undecoded reads rejected by length filter
- `undecoded_reason_len_mismatch`: sampled undecoded reads where the decoder's `len_out_of_range` reason and the validator's
  own length re-classification disagree. Not computed (0, and `len_conf_missing` set in the JSON) when the sample has no
  `length_window_stats.tsv` row (`length_conf_missing` = 1)
- The JSON summary additionally carries `undecoded_missing` / `decoded_missing` flags per sample, and the re-checked undecoded
  sample is written to `undecoded_sample_recheck_<sample>_<N>.tsv`

### Compare top hits across runs (interactive)
```bash
python3 06_compare_top_hits.py \
  --runs DELeGANce_out/SampleA_run DELeGANce_out/SampleB_run \
  --roles active inactive \
  --labels SampleA SampleB \
  --preset glm_full_dev_cuda_fp32 \
  --top-n 100 \
  --recommend-n 10 \
  --out-dir DELeGANce_out/compare_runs
```
Notes:
- Use `--top-n-list` and `--recommend-n-list` to set per-run counts (comma/space-separated).
- Use `--labels` to set display names; these are used for HTML labels and sample column prefixes.
- If runs use different presets, pass each run's `05_hybrid_annot.tsv` path to `--runs` instead of `--preset`.
- Use `--fill-scores 1` to populate per-run score columns even when a compound is not in that run's top N.
- Labels: when `--labels` is omitted, a run given as a directory is labelled by its basename; a run given as a
  `05_hybrid_annot.tsv` path is labelled `<run>_<preset>` (the two directories above the file, skipping `03_normalized`).
  Duplicate derived labels get `_1`, `_2`, ... suffixes (a warning is printed); duplicate explicit `--labels` are an error.
- `--out-prefix NAME` without a directory component is created under `--out-dir`; a prefix with a directory (or an absolute
  path) is used as-is. `compare_top<N>_<label>_bb_frequency.tsv` is only written when `--include-summary 1`.
- `--bbavg-missing skip|zero` (default `skip`) controls how `bbavg` clustering treats BB positions where only one of the two
  compounds has a fingerprint: `skip` averages over positions valid in both compounds (two compounds sharing a single valid BB
  can reach similarity 1.0); `zero` counts such positions as similarity 0 and divides by the number of positions where at least
  one compound has a fingerprint. Positions empty in both compounds (e.g. `bb4_smiles` of a 3-cycle library) never count in
  either mode.
- Diverse lists (`compare_top<N>_<label>_diverse.tsv`, `tier_report_*_diverse.tsv`) contain cluster representatives only. When
  clustering is not performed (`--cluster 0`, `--include-summary 0`, RDKit missing, no `bb*_smiles` columns, or no valid
  fingerprints) the files are still written but contain only the header, and an `[INFO] clustering not performed ...` line is
  printed.
- `--roles` must assign each of `active`, `inactive`, `both` to at most one run; the specificity report needs one `active` and
  one `inactive` run (otherwise it is skipped with a warning).
- Without bokeh the script prints a warning and writes the TSV outputs only (`--no-html` gives the same result explicitly).
- Inputs whose key columns lack the `_x` suffix (`ID`, `LIB_ID`, `BB1`..) are accepted and normalised with a `[WARN]`.
- Clustering defaults to `bbavg` (per-BB average). Use `--cluster-mode compound_or` to revert to OR fingerprints.
- If two prefixed sample columns are identical across the candidate table (for example shared controls),
  the HTML deduplicates them to avoid repeated values.
- For 2 to 3 runs, the HTML includes Venn cell tabs (for example A-only, A+B, A+B+C) with per-cell tables.
- Use `--include-summary 0` to skip per-run summary plots, and `--include-specificity 0` to skip specificity outputs.
- Specificity uses `--roles` (active/inactive/both) and supports `--spec-prefix`, `--spec-top-n`, and `--active-spec-*` / `--inactive-spec-*` / `--both-spec-*` cutoffs.
- Group cutoffs use rank_pct percentiles per run (example: 99 = top 1 percent within that run).

### Specificity report (selectivity and diversity)
```bash
python3 07_tiered_report.py \
  --active-run DELeGANce_out/SampleA_run \
  --inactive-run DELeGANce_out/SampleB_run \
  --labels SampleA SampleB \
  --preset glm_full_dev_cuda_fp32 \
  --top-n 1000 \
  --out-dir DELeGANce_out/tier_report
```
Notes:
- Specificity uses only active and inactive rank_pct for group definitions and scoring.
- selectivity_score = active_rank_pct - inactive_rank_pct
- both_specific_score = (active_rank_pct + inactive_rank_pct) / 2
- Candidate pool is the union of top N from each run, filtered by GLM_hit/RS_pass/Consensus_hit and NEG_hard_fail (disable with `--no-hit-filter`).
- Use `--top-n 0` to include all compounds from each run (still applies hit/QC filters). In this mode, all-candidates Excel files are skipped (TSV only) to avoid huge spreadsheets.
- Optional NEG filter: `--neg-samples K_R2C5 K_R3C5 --neg-max-pct 99` removes candidates with NEG CPM in the top 1% of any listed NEG sample.
  Percentiles are computed across the full run (all compounds in each run), not just the top-N candidate subset.
- Use `--group-style plain` to label groups as Active/Inactive/Common (no “specific” wording).
- Use `--no-hit-filter` to include all compounds regardless of GLM/RS/Consensus/NEG QC flags (use with care; output can be very large).
- Optional final list tab: `--final-hits DELeGANce_out/tier_report/final_hits.tsv` embeds a "Final hits" tab in the HTML (auto-detects `final_hits.tsv` in `--out-dir` if not provided).
- Final hit selection (writes `final_hits.tsv/.xlsx`):
  `--final-active-n 15 --final-inactive-n 15 --final-common-n 10` (Common = Both-specific).
  Picks cluster reps first, then fills from all hits in each group. When any `--final-*-n` is set, it overrides
  `--final-hits` for the HTML Final hits tab.
- Group ranking default is enrichment-based: per-group median CPM (fallback to raw counts if CPM unavailable).
  Enrichment excludes NEG samples (`--neg-samples`), the DEL2 baseline (`--del2`, default `DEL2`; use the same name as
  `03_call_hits.py --del2_col`) and `--exclude-samples` (default `DEL234`).
- When `--labels` is omitted, labels are derived from the paths: directory inputs use their basename; `05_hybrid_annot.tsv`
  file inputs use the run root name (`<run>/03_normalized/<preset>/05_hybrid_annot.tsv`). Duplicate labels get a `_2`, `_3` suffix.
- In the Final hits tab, search/paging/CSV keep the group order (active → inactive → common) and sort by the chosen rank
  column within each group.
- NEG filter: a NEG column whose percentile cutoff is 0 keeps rows with NEG == 0; if the filter leaves no candidate the
  script exits with code 1.
  Use `--rank-by specificity` to revert to specificity-based ranking. Adjust aggregation with `--enrich-agg`
  (`median|mean|max`) and common-group logic with `--common-enrich` (`min|mean|gmean`).
- HTML pagination: `--table-page-size 50` controls rows per page; the table height expands to show the full page (no vertical scroll). `--max-table` caps total rows loaded per table.
- HTML "Download CSV" exports the full filtered table (not just the current page).
- HTML tables display missing values as `-` (keeps real values intact without implying zeros).
- Unprefixed sample columns (e.g., `K_R2C1`, `K_R2C1_CPM`) are coalesced from prefixed run columns when available
  (active → inactive → both). If still missing, they remain `-`.
- Sample column display mode for HTML tables: `--sample-cols-mode coalesced|prefixed|both` (default: coalesced).
- Group label style in outputs: `--group-style specific|plain` (default: specific). Use `plain` to avoid the “specific” wording.
- Identical prefixed sample columns (for example shared controls across runs) are deduplicated in the HTML tables.
- Group defaults (rank_pct percentiles per run):
  SampleA-specific (SampleA >= 99, SampleB <= 50), SampleB-specific (SampleB >= 99, SampleA <= 50),
  Common (SampleA >= 99 and SampleB >= 99; via `--both-spec-min`).
- Diverse tables are cluster representatives (cluster_rep=1 or cluster_medoid=1).
- Clustering similarity default is `bbavg` (per-BB average). Use `--cluster-mode compound_or` for OR fingerprints.
- Plot ranges: `--plot-x-range auto` / `--plot-y-range auto` (default) or fixed ranges like `99,100`.
- Use `--html-mode inline` to embed all JS/CSS for offline sharing (larger file size).

`undecoded_unexpected_decoded` reflect the settings difference rather than decoder errors:
- `--mismatch none|hp_op_cp` (default `hp_op_cp`): must equal the decode run's `--mismatch`. Validating a `--mismatch none`

- `--max-cp-cands N`, `--max-anchor-cands N` (default 0 = unlimited): must equal the decode run's `--max-cp-cands` /
  `--max-anchor-cands`. With a cap the re-check truncates candidates exactly as the decoder does.
- The values actually used by the decoder are printed in its log as `Effective config: ...` (`02_decoded/` has no parameter
  file yet).
- `--decoded-max-lines` and `--decoded-sample` are alternatives: when `--decoded-sample N` > 0 the reservoir sample is
  validated and `--decoded-max-lines` is ignored. Pass only one of them.

## Troubleshooting

- fastp missing: Install fastp or run with `--skip-fastp` and provide merged FASTQs in `01_fastp_out/`.
- skip-fastp decode errors: Ensure `01_fastp_out/*_merged.fq(.gz)` exists and `BB_information_fixed.tsv` is present under the run root.
- Decode rate is low: Check BB file, `--length-tol`, and `--adj-tol`.
- Quick validation: Use `--decoded-max-lines` to cap decoded lines per sample; set 0 for full validation.
- Random validation: Use `--decoded-sample` for reservoir sampling (scans the file once but validates only N reads).
- No merged FASTQs found: Ensure preprocess ran or provide `<SAMPLE>_merged.fq.gz` files in `01_fastp_out/`.
- GPU GLM top mode: `--glm_mode=top` defaults to CPU for stability. Override with `--force_gpu_top=1` or `DELEGANCE_FORCE_GPU_TOP=1` (for `run_delegance_pipeline.py`, use `--force-gpu-top 1`).
- Interactive report fails (narwhals): If bokeh complains about missing narwhals, install narwhals and re-run `04_build_interactive_report.py`.
