# DELeGANce Screening Pipeline

DELeGANce is an end-to-end pipeline for DNA-encoded library (DEL) sequencing analysis. It covers FASTQ preprocessing, barcode decoding, hit calling (GLM-based), and reporting (static and interactive).

---

## Quick Start (Beginner)

Where to run commands
- If you are in the repo root (this folder), run `python3 run_delegance_pipeline.py`.
- If you call from a parent folder, prefix paths with the repo directory name.
- `--output-dir` is resolved relative to your current working directory.

### 1) Create a clean environment
Option A (recommended, reproducible):
```bash
conda env create -f environment.yml
conda activate delegance
```

Option B (manual install):
```bash
conda create -n delegance python=3.10
conda activate delegance
conda install -c conda-forge -c bioconda fastp
conda install -c conda-forge numpy pandas scipy matplotlib bokeh narwhals
# Optional (recommended for structure + speed)
conda install -c conda-forge rdkit
```

GPU (optional):
```bash
conda install -c pytorch -c nvidia pytorch-cuda=12.1
```

### 2) Run the pipeline
```bash
python3 run_delegance_pipeline.py \
  --fastq-dir 00_input_fastq \
  --bbinfo 00_BB_information.txt \
  --output-dir DELeGANce_out/my_run \
  --threads 6 \
  --mismatch hp_op_cp \
  --r1 R1C1 R1C2 R1C3 R1C4 \
  --r2 R2C1 R2C2 R2C3 R2C4 \
  --neg NEG_R1 NEG_R2 \
  --del2 DEL2
```

### 3) Open the results
- `DELeGANce_out/my_run/index.html`
- `DELeGANce_out/my_run/03_normalized/<preset>/interactive_hits.html`

## Inputs (What You Need)

### 1) FASTQ naming
Each sample should have paired reads:
```
<SAMPLE>_1.fastq.gz
<SAMPLE>_2.fastq.gz
```
`<SAMPLE>` becomes your column name in downstream tables.

### 2) BB information file (tab-delimited)
Minimum 7 columns in this exact order (header optional):
```
type    seq     bb_id   cycle   tag_id  lib_id  smiles
```
Notes:
- `type` must include CODON/HP/OP/CP
- `cycle` is 1/2/3/4 for codons
- `lib_id` is required if multiple libraries exist
- BB files are user-provided and are not stored in this repository

### 3) Sample columns for hit calling
These must match the column names inside:
```
DELeGANce_out/<run_name>/02_decoded/raw_counts_matrix.tsv
```
Use those exact names in `--r1`, `--r2`, `--neg`, `--del2`.

## What the Pipeline Does (High Level)

1) Preprocess (fastp)
   - trims, merges pairs, creates `01_fastp_out/`
2) Decode (HP/OP/Codons/CP)
   - builds `02_decoded/` with raw/scaled count matrices
3) Hit calling + reports
   - GLM scoring plus static and interactive reports in `03_normalized/`

---

## Decoding Logic (Important)

The decoder expects the read layout:
```
HP - OP - Codon1 - Codon2 - Codon3 - (Codon4) - CP
```

Rules enforced by the code:
- Decode: HP/OP/CP allow 1-bp mismatch (substitution, insertion, deletion) when `--mismatch hp_op_cp` is enabled.
- Preprocess: mismatch indexing is substitution-only for HP/OP/CP (codons are always perfect match only). This does not remove indel tolerance during decode.
- Use `--mismatch hp_op_cp|none` to control mismatch handling across preprocess + decode.
- Codons are perfect match only
- Order is strict; violations are marked undecoded
- Small overlap or insertion between blocks is allowed within `ADJ_TOL`
- revcomp is handled by re-orienting the read and applying the same rules

Key parameters (advanced):
- `--adj-tol` in `02_decode_reads.pl` (default 3)
- `--length-tol` in `02_decode_reads.pl` (default 5; fastp auto mode can adjust)
- `--max-cp-cands` / `--max-anchor-cands` in `02_decode_reads.pl` (0 = no limit; default 0)

---

## Resume and Partial Runs

If a run is interrupted, the pipeline checks completion markers before skipping stages:
- Preprocess: requires merged FASTQs, `BB_information_fixed.tsv`, and `01_preprocess_reads.log` containing `All done.`
- Decode: requires `raw_counts_matrix.tsv` and `02_decode_reads.log` containing `All done.`

If these markers are missing, the pipeline reruns the stage.

## How to Pick Hits (Beginner)

The QC export adds two helper fields:
- `Tier`: A = consensus hit with no QC flags (recommended), B = consensus hit with QC flags (control or risk check)
- `PickGroup`: TierA_Top, TierA_Diverse, TierB_Control

Recommended starting set: TierA_Top plus a few TierB_Control for controls.

## Column Reference (Key Outputs)

This section explains columns used in major TSV outputs. Sample-specific columns use the exact sample names from `raw_counts_matrix.tsv` and are described as patterns.

### 02_decoded/raw_counts_matrix.tsv
- `lib_id`: library ID assigned from CP (or NA if unknown)
- `id`: decoded tag ID string (cycles_BB1_BB2_BB3_[BB4])
- `<sample>`: raw decoded read count for that sample

### 02_decoded/scaled_counts_matrix.tsv
- Same columns as `raw_counts_matrix.tsv`
- Values are CPM scaled by `--scaling-denom` (default: `sample_decoded`)

### 02_decoded/sample_stats.tsv
- `sample`: sample name derived from FASTQ basename
- `total_reads`: merged reads processed
- `length_passed_reads`: reads within the expected length window
- `decoded_reads`: reads that passed decoding
- `decode_rate_pct`: decoded_reads / total_reads * 100

### 02_decoded/decoding_summary.tsv
- `sample`: sample name
- `total_reads`: merged reads processed
- `decoded_reads`: reads that passed decoding
- `no_cp`: reads without a valid CP
- `no_op`: reads without a valid OP
- `no_hp`: reads without a valid HP
- `codon_fail`: reads failing codon matching (codons require perfect match)
- `len_out_of_range`: reads outside the accepted length window
- `order_violation`: reads with HP/OP/Codon/CP order violations

### 02_decoded/qc_checks.tsv
- `sample`: sample name
- `codon_len_not9`: decoded reads where codon length is not 9
- `order_violation`: decoded reads with order violations
- `cp_len_out_of_27_29`: decoded reads with CP length outside 27 to 29

### 03_normalized/<preset>/05_hybrid_annot.tsv
- `LIB_ID_x`: library ID from decoded tags (CP-based)
- `ID_x`: decoded tag ID from count matrix
- `cycles`: 3 or 4 cycles inferred from the tag
- `BB1_x`, `BB2_x`, `BB3_x`, `BB4_x`: decoded BB IDs (may include LIB suffix)
- `CP_x`: decoded CP ID
- `mean_R1_norm`, `mean_R2_norm`: mean normalized counts across R1/R2 columns
- `DEL2_norm`: normalized DEL2 count
- `CV_R1`, `CV_R2`: coefficient of variation across R1/R2 replicates
- `LFC_R1_vs_DEL2_baseline`, `LFC_R2_vs_DEL2_baseline`: baseline log2 fold-change vs DEL2
- `mean_NEG1_norm`, `mean_NEG2_norm`: mean normalized NEG counts (for each NEG set)
- `LFC_NEG_R1_vs_DEL2`, `LFC_NEG_R2_vs_DEL2`: NEG vs DEL2 log2 fold-change (raw)
- `delta_NEG_R1`, `delta_NEG_R2`: NEG deltas for R1/R2
- `delta_R1`, `delta_R2`: deltas for R1/R2 (effect size)
- `LFC_NEG_R1_vs_DEL2_glm`, `LFC_NEG_R2_vs_DEL2_glm`: GLM-adjusted NEG log2 fold-change
- `LFC_R1_vs_DEL2`, `LFC_R2_vs_DEL2`: GLM-adjusted log2 fold-change vs DEL2
- `mu_NEG_R1_hat`, `mu_NEG_R2_hat`, `mu_R1_hat`, `mu_R2_hat`: GLM fitted mean counts
- `alpha_for_penalty`: dispersion parameter used for penalty (capped)
- `delta_NEG`: combined NEG delta
- `LFC_NEG_vs_DEL2`: combined NEG log2 fold-change
- `mu_NEG_hat`: GLM fitted mean for NEG
- `DEL2_sum`: sum of DEL2 counts used by GLM
- `LFC_R1_vs_DEL2_baseline_glm`, `LFC_R2_vs_DEL2_baseline_glm`: GLM baseline LFC values
- `LFC_R1_vs_DEL2_used`, `LFC_R2_vs_DEL2_used`: LFC values used for scoring after gating
- `LFC_NEG_R1_vs_DEL2_used`, `LFC_NEG_R2_vs_DEL2_used`: NEG LFC values used for scoring
- `NEG_control_used`: NEG control selection used in scoring
- `LFC_NEG_vs_DEL2_used`: combined NEG LFC used for scoring
- `delta_NEG_used`: NEG delta used for penalty
- `NEG_penalty_used`: NEG penalty mode used in scoring
- `E_component`: effect-size term used in HitScore
- `W_count`: count-based weight term (logistic of mean counts)
- `E_for_synthon`: effect term used for synthon scoring
- `SynthonScore`: synthon consistency score
- `SynthonBonus`: multiplicative bonus (1 + rho_syn * SynthonScore)
- `Penalty_NEG_R1`, `Penalty_NEG_R2`: NEG penalties per arm
- `Penalty_NEG`: total NEG penalty
- `Penalty`: total penalty (CV/alpha and NEG penalties)
- `HitScore_GLM`: GLM hit score (E_component * W_count * SynthonBonus - Penalty)
- `HitScore_pct`: percentile of HitScore_GLM within the run (0 to 100)
- `GLM_hit`: GLM pass/fail flag
- `avg_R1`, `sd_R1`, `avg_R2`: ReadScaler mean and sd of raw counts
- `zscore_avgR1`: z-score of avg_R1
- `mean_log2FC_DEL2`, `sd_log2FC_DEL2`, `se_log2FC_DEL2`, `p_DEL2`: DEL2 ReadScaler stats
- `mean_log2FC_BEAD`, `sd_log2FC_BEAD`, `se_log2FC_BEAD`, `p_BEAD`: BEAD ReadScaler stats (R1)
- `mean_log2FC_BEAD_R2`, `sd_log2FC_BEAD_R2`, `se_log2FC_BEAD_R2`, `p_BEAD_R2`: BEAD ReadScaler stats (R2)
- `log2Boost_R2vsR1`: log2 boost of R2 vs R1
- `mean_log2Boost_R2vsR1_paired`, `sd_log2Boost_R2vsR1_paired`, `se_log2Boost_R2vsR1_paired`, `n_pairs_paired`, `p_BoostPaired`: paired boost stats
- `q_DEL2`, `q_BEAD`, `q_BEAD_R2`, `q_BoostPaired`: BH-adjusted q-values
- `mad_log2FC_DEL2`, `mad_log2FC_BEAD`, `mad_log2Boost_R2vsR1_paired`: MAD values for variance penalty
- `var_penalty`: variance penalty used in ReadScaler
- `HitScore_RS`: ReadScaler hit score
- `fail_reasons`: semicolon list of QC failures
- `pass_filters`: QC pass flag
- `<sample>`: raw decoded read count for that sample
- `<sample>_CPM`: CPM for that sample
- `bb1_id`, `bb1_smiles`, `bb1_tag_uid`, `bb1_tag_seq`: BB1 metadata from BB info file
- `bb2_id`, `bb2_smiles`, `bb2_tag_uid`, `bb2_tag_seq`: BB2 metadata
- `bb3_id`, `bb3_smiles`, `bb3_tag_uid`, `bb3_tag_seq`: BB3 metadata
- `bb4_id`, `bb4_smiles`, `bb4_tag_uid`, `bb4_tag_seq`: BB4 metadata
- `BB_SMILES_CONCAT`: concatenated BB SMILES (for clustering)
- `ID_y`, `LIB_ID_y`, `BB1_y`, `BB2_y`, `BB3_y`, `BB4_y`, `CP_y`: BB info merge fields
- `RS_pass`: ReadScaler pass flag
- `NEG_hard_fail`: hard fail due to NEG gating
- `LFC_NEG_centered`: NEG vs DEL2 LFC centered by null subset
- `delta_NEG_centered`: centered NEG delta
- `NEG_center_fail`: fail if LFC_NEG_centered exceeds threshold
- `LFC_NEG_centered_R1`, `NEG_center_shift_R1`: R1 centering detail
- `LFC_NEG_centered_R2`, `NEG_center_shift_R2`: R2 centering detail
- `Consensus_hit`: GLM_hit and RS_pass

### 03_normalized/<preset>/top<N>_hits.tsv
- Inherits columns from `05_hybrid_annot.tsv`
- Adds `compound_key` (BB1|BB2|BB3|BB4 with LIB suffix removed)
- Adds `rank` (1 = best), `rank_pct` (percentile within top N), `score_z` (z-score of the run score)
- Adds `cluster_id`, `cluster_size`, `cluster_rep`, `cluster_medoid` (when clustering is enabled)

### 03_normalized/<preset>/top<N>_recommended.tsv
- Same columns as `top<N>_hits.tsv`
- Rows filtered by QC rules (Consensus_hit, GLM_hit, RS_pass, NEG_hard_fail, if columns exist)

### 03_normalized/<preset>/top<N>_diverse.tsv
- Same columns as `top<N>_recommended.tsv`
- Subset of cluster representatives (`cluster_rep=1` or `cluster_medoid=1`)

### 03_normalized/<preset>/top<N>_bb_frequency.tsv
- `bb_col`: BB column name (BB1_x, BB2_x, BB3_x, BB4_x)
- `bb`: BB ID (LIB suffix removed)
- `count`: number of appearances in top N
- `pct`: percent of top N
- `lib_ids`: unique LIB_ID list for the BB
- `lib_counts`: per-LIB_ID counts (aligned with lib_ids)

### 03_normalized/<preset>/top<N>_clusters.tsv
- `cluster_id`: cluster label
- `cluster_size`: number of hits in the cluster
- `rep_index`: row index of the score-based representative
- `rep_ID_x`, `rep_score`, `rep_BB1_x`..`rep_BB4_x`, `rep_CP_x`, `rep_compound_key`: representative fields
- `medoid_index`, `medoid_ID_x`, `medoid_score`, `medoid_compound_key`, `medoid_avg_sim`: medoid fields

### compare_top<N>_union_top<N>.tsv and compare_top<N>_overlap_top<N>.tsv
- `compound_key`: BB1|BB2|BB3|BB4 with LIB suffix removed
- `pattern`: membership pattern (example: A, B, A+B)
- `n_runs`: number of runs containing the compound in top N
- `<label>_score`: per-run score (HitScore_GLM or HitScore_RS)
- `<label>_score_z`: z-score of the per-run score
- `<label>_HitScore_pct`: per-run HitScore percentile
- `<label>_rank`: rank within that run
- `<label>_rank_pct`: rank percentile within that run

### compare_top<N>_pattern_counts.tsv
- `pattern`: membership pattern
- `count`: number of compounds in the pattern
- `pct`: percentage of the union

### compare_top<N>_<label>_top<N>.tsv
- Same columns as `top<N>_hits.tsv` for that run

### compare_top<N>_<label>_recommended<M>.tsv
- Same columns as `top<N>_recommended.tsv` for that run

### compare_top<N>_<label>_diverse.tsv
- Same columns as `top<N>_diverse.tsv` for that run

### tier_report_*_all_candidates.tsv and tier_report_*_specific.tsv
- Inherits columns from `top<N>_hits.tsv`
- Adds `rank`: rank in the combined candidate pool
- Adds `active_score`, `active_rank`, `active_rank_pct`, `active_score_z`, `active_hit_pct`: metrics from the active run
- Adds `inactive_score`, `inactive_rank_pct`: metrics from the inactive run
- Adds `both_score`, `both_rank_pct`: metrics from the optional both run (NaN if not provided)
- Adds `selectivity_score`: active_rank_pct - inactive_rank_pct
- Adds `inactive_selectivity_score`: inactive_rank_pct - active_rank_pct
- Adds `both_specific_score`: (active_rank_pct + inactive_rank_pct) / 2
- Adds `group_code`: Active-specific, Inactive-specific, Both-specific, or Other
- Adds `specificity_score`: score used for group ranking (selectivity_score or both_specific_score)
- Adds `group_rank`: rank within group by specificity_score
- Adds `group`: display label (from `--labels`)
- Adds `<label>_<sample>` and `<label>_<sample>_CPM`: raw and CPM columns from each run with label prefix

### tier_report_*_diverse.tsv
- Same columns as tier_report_*_specific.tsv
- Subset of cluster representatives (cluster_rep=1 or cluster_medoid=1)

### run_full_validation.py outputs (decode_validation_summary.tsv)
- `run`: validation run name
- `sample`: sample name
- `total_reads`, `length_passed_reads`, `decoded_reads`, `decode_rate_pct`: same definitions as decode stats
- `no_cp`, `no_op`, `no_hp`, `codon_fail`, `len_out_of_range`, `order_violation`: decode failure counts
- `qc_codon_len_not9`, `qc_order_violation`, `qc_cp_len_out_of_27_29`: QC check counts
- `validation_pass`: decoded reads that match expected BBs/length/order in validation
- `validation_fail`: decoded reads that fail validation checks
- `validation_cycles_mismatch`: decoded reads with cycle count mismatch
- `validation_length_filter_reject`: decoded reads failing expected length
- `validation_lib_unknown`: decoded reads with unknown library ID
- `length_conf_missing`: missing length configuration for the sample
- `undecoded_sampled`: number of undecoded reads sampled for validation
- `undecoded_unexpected_decoded`: sampled undecoded reads that appear decodable
- `undecoded_len_reject`: sampled undecoded reads rejected by length filter
- `undecoded_reason_len_mismatch`: sampled undecoded reads with length mismatch vs expected

## Common Commands

### Hit calling only (after decode)
```bash
python3 03_call_hits.py \
  --run_root DELeGANce_out/my_run \
  --r1_cols R1C1 R1C2 R1C3 R1C4 \
  --r2_cols R2C1 R2C2 R2C3 R2C4 \
  --neg_r1_col NEG_R1 \
  --neg_r2_col NEG_R2 \
  --del2_col DEL2 \
  --preset balanced
```

### Regenerate interactive report
```bash
python3 04_build_interactive_report.py \
  --master_tsv DELeGANce_out/my_run/03_normalized/<preset>/05_hybrid_annot.tsv \
  --bbinfo DELeGANce_out/my_run/BB_information_fixed.tsv \
  --out DELeGANce_out/my_run/03_normalized/<preset>/interactive_hits.html
```

### Summarize top hits and interactive HTML
```bash
python3 05_summarize_top_hits.py \
  --output-dir DELeGANce_out/my_run \
  --preset glm_full_dev_cuda_fp32 \
  --top-n 100 \
  --recommend-n 10
```
Notes:
- Uses HitScore_GLM when available (fallback: HitScore_RS)
- Recommended hits require Consensus_hit=1, GLM_hit=1, RS_pass=1, NEG_hard_fail=0 (if columns exist)
- HTML requires bokeh (narwhals may be required depending on bokeh version; BB hover images also require rdkit)
- BB frequency bars are grouped by BB_ID (structure); hover shows contributing LIB_ID list
- Clustering uses BB SMILES to build a combined fingerprint and Butina clustering (Tanimoto >= 0.7 by default)
- Clustering options: `--cluster 0`, `--cluster-sim 0.7`, `--cluster-radius 2`, `--cluster-nbits 2048`
- Representative selection: `--cluster-rep score|medoid` (default: score). `medoid` picks the member with
  highest average Tanimoto similarity within the cluster; ties break by score/percentile/CPM/reads.

### Compare top hits across runs (interactive)
```bash
python3 06_compare_top_hits.py \
  --runs DELeGANce_out/SampleA_run DELeGANce_out/SampleB_run \
  --roles active inactive \
  --labels SampleA SampleB \
  --preset glm_full_dev_cuda_fp32 \
  --top-n 100 \
  --recommend-n 10 \
  --out-dir DELeGANce_out/compare_runs
```
Notes:
- Use `--top-n-list` and `--recommend-n-list` to set per-run counts (comma/space-separated).
- Use `--labels` to set display names; these are used for HTML labels and sample column prefixes.
- If runs use different presets, pass each run's `05_hybrid_annot.tsv` path to `--runs` instead of `--preset`.
- Use `--fill-scores 1` to populate per-run score columns even when a compound is not in that run's top N.
- For 2 to 3 runs, the HTML includes Venn cell tabs (for example A-only, A+B, A+B+C) with per-cell tables.
- Use `--include-summary 0` to skip per-run summary plots, and `--include-specificity 0` to skip specificity outputs.
- Specificity uses `--roles` (active/inactive/both) and supports `--spec-prefix`, `--spec-top-n`, and `--active-spec-*` / `--inactive-spec-*` / `--both-spec-*` cutoffs.
- Group cutoffs use rank_pct percentiles per run (example: 99 = top 1 percent within that run).

### Specificity report (selectivity and diversity)
```bash
python3 07_tiered_report.py \
  --active-run DELeGANce_out/SampleA_run \
  --inactive-run DELeGANce_out/SampleB_run \
  --labels SampleA SampleB \
  --preset glm_full_dev_cuda_fp32 \
  --top-n 1000 \
  --out-dir DELeGANce_out/tier_report
```
Notes:
- Specificity uses only active and inactive rank_pct for group definitions and scoring.
- selectivity_score = active_rank_pct - inactive_rank_pct
- both_specific_score = (active_rank_pct + inactive_rank_pct) / 2
- Candidate pool is the union of top N from each run, filtered by GLM_hit/RS_pass/Consensus_hit and NEG_hard_fail.
- Optional NEG filter: `--neg-samples K_R2C5 K_R3C5 --neg-max-pct 99` removes candidates with NEG CPM in the top 1% of any listed NEG sample.
- Optional final list tab: `--final-hits DELeGANce_out/tier_report/final_hits_40.tsv` embeds a "Final hits" tab in the HTML (auto-detects `final_hits_40.tsv` or `final_hits.tsv` in `--out-dir` if not provided).
- Final hit selection (writes `final_hits.tsv/.xlsx` and `final_hits_<total>.tsv/.xlsx`):
  `--final-active-n 15 --final-inactive-n 15 --final-common-n 10` (Common = Both-specific).
  Picks cluster reps first, then fills from all hits in each group. When any `--final-*-n` is set, it overrides
  `--final-hits` for the HTML Final hits tab.
- HTML pagination: `--table-page-size 50` controls rows per page. `--max-table` caps total rows loaded per table.
- HTML tables display missing values as `-` (keeps real values intact without implying zeros).
- Group defaults (rank_pct percentiles per run):
  SampleA-specific (SampleA >= 99, SampleB <= 50), SampleB-specific (SampleB >= 99, SampleA <= 50),
  Common (SampleA >= 99 and SampleB >= 99; via `--both-spec-min`).
- Diverse tables are cluster representatives (cluster_rep=1 or cluster_medoid=1).
- Plot ranges: `--plot-x-range auto` / `--plot-y-range auto` (default) or fixed ranges like `99,100`.

## Troubleshooting

- fastp missing: Install fastp or run with `--skip-fastp` and provide merged FASTQs in `01_fastp_out/`.
- skip-fastp decode errors: Ensure `01_fastp_out/*_merged.fq(.gz)` exists and `BB_information_fixed.tsv` is present under the run root.
- Decode rate is low: Check BB file, `--length-tol`, and `--adj-tol`.
- Quick validation: Use `--decoded-max-lines` to cap decoded lines per sample; set 0 for full validation.
- Random validation: Use `--decoded-sample` for reservoir sampling (scans the file once but validates only N reads).
- No merged FASTQs found: Ensure preprocess ran or provide `<SAMPLE>_merged.fq.gz` files in `01_fastp_out/`.
- GPU GLM top mode: `--glm_mode=top` defaults to CPU for stability. Override with `--force_gpu_top=1` or `DELEGANCE_FORCE_GPU_TOP=1` (for `run_delegance_pipeline.py`, use `--force-gpu-top 1`).
- Interactive report fails (narwhals): If bokeh complains about missing narwhals, install narwhals and re-run `04_build_interactive_report.py`.

## Repository Layout

- `run_delegance_pipeline.py` - orchestrator (preprocess -> decode -> hit calling)
- `01_preprocess_reads.pl` - FASTQ preprocessing and fastp integration
- `02_decode_reads.pl` - barcode decode and count matrices
- `03_call_hits.py` - GLM hit calling and static report
- `04_build_interactive_report.py` - interactive Bokeh report
- `05_summarize_top_hits.py` - summarize top N hits and recommend top X compounds
- `06_compare_top_hits.py` - compare top hits across runs and interactive HTML
- `07_tiered_report.py` - specificity and diversity report
- `export_beginner_qc_report.py` - beginner QC HTML and TSV
- `export_final_excel.py` - Excel export with guide tab
- `subsample_fastq_pairs.py` - FASTQ subsampling helper
- `DELeGANce_out/` - outputs
